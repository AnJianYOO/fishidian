# 改代码时必须同步改的文档

> 这份表的目的只有一个：**改完代码当场就把文档改了，不等下次、不等别人提醒。**
> 新增一行规则的成本是一分钟；漏更新一次文档的成本是用户某天读到的规格和实际行为对不上，而且没人知道该信哪份。
>
> 表里写「内部档案」的地方，是作者本地的规划与决策记录，没有随仓库公开。看到这种标注就知道那份文件不在这，按左列代码和公开文档改就行。

## 用法

改完代码，先在下表第一列找到你动过的文件，右边每一份都要过一遍：对得上就不动，对不上就**当场**改掉。

## 三条容易漏的

1. **桥的版本号和 CHANGELOG**。桥有独立的 `CHANGELOG.md` 和 `package.json` 版本，改了 `lib/` 就必须两处都动。分条发送那版就漏过一次：代码已经是新内容，版本号还停在上一个，排查时先多绕了一圈。
2. **同一份桥代码在磁盘上有三个副本，「小鱼」窗口加载的是第三份**：
   - `%USERPROFILE%\dsh-qq-onebot-bridge\lib\bridge.js`（用来调试、拷来拷去的）
   - 本地的 `dsh-qq-onebot-bridge\lib\bridge.js`（源码，打包器从这份取）
   - `%USERPROFILE%\.dsh-fatfish\profiles\desktop\node_modules\dsh-qq-onebot-bridge\lib\bridge.js`（**真正被加载的那份**，pnpm 装的独立拷贝，不是链接）

   前两处改完、第三处没改，重启后跑的仍是旧代码，症状就是「我明明改了、也重启了，怎么还是老样子」。三处都要覆盖，覆盖前先 `Compare-Object` 确认只差你改动的那几行。
3. **重建包之后再自检**。直接拷 `tools\install_v0.1.0.ps1` 去跑没用，包里是旧副本，必须先重建。

## 重启「小鱼」窗口的正确姿势

`--user-data-dir` 只换 Electron 的数据目录，**决定加载哪个 profile 的是环境变量 `DSH_HOME`**。只传 `--user-data-dir` 会开成主工作窗口，标题显示「DeepSeek Harness」而不是「小鱼」。

```
$env:DSH_HOME = "$env:USERPROFILE\.dsh-fatfish"
Start-Process -FilePath "$env:LOCALAPPDATA\Programs\DeepSeek Harness\DeepSeek Harness.exe" `
              -ArgumentList "--user-data-dir=$env:USERPROFILE\.dsh-fatfish\electron-data"
```

起来之后的三条判据：窗口标题是「小鱼」、`127.0.0.1:8798` 在 LISTENING（webhook）、`127.0.0.1:6700` 有 ESTABLISHED（NapCat 反连上了）。三条都满足才算桥真的跑起来。

## 什么时候这份表需要更新

新增一个模块、或者发现某份文档存在但表里没提到它 —— 就是该加一行的时候。表本身也按这份表的规矩来改。
