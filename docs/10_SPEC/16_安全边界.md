# 16 安全边界

> 状态：已确定 ｜ 最后更新：2026-11-10 ｜ 对应版本：通用
> 待从归档的 `01_安全约束.md` 抽取，这里只放"现在守什么"，不放"为什么"。

## 现在守住的几条
### 1 凭据不进安装包

token、WebUI 口令、QQ 号、白名单里的具体号码，全部在打包前替换成占位符，或删掉。`打包干净度自检.ps1` 负责扫这件事，有阻断级规则。

### 2 凭据不出现在任何对外输出

不贴截图、不发日志原文、不在文档里写实值。日志里的 QQ 号只留后四位。

### 3 本地服务只监听回环

8799 只 `127.0.0.1`，不 `0.0.0.0`。带随机 token 拼进 URL。

### 4 改状态必须 POST

不接受 GET 改配置，防止别的网页用 `<img src>` 把白名单改了。

### 5 跨域预检必须答 OPTIONS

不答的话浏览器会直接掐掉请求，表现是"页面点了保存、看起来成功了、实际什么都没写"。

### 6 卸载不动用户数据

卸载不删 `workspace\`。

### 7 不碰第三方工具

NapCat 是别人的工具，不随大肥鱼的卸载一起删掉。

## 8 哪些数据能出这台机器

| 数据 | 能不能出去 | 规则 |
| --- | --- | --- |
| 记忆库原文（`dfy.db`） | **不能** | 那是她记得的东西，不出本机、不进任何日志转发 |
| QQ 号、白名单号码 | 不能 | 对外只留后四位 |
| token、WebUI 口令 | 不能 | 不进文档、不进截图、不进安装包 |
| 脱敏后的报错片段 | 能 | 只给"哪一步失败 + 报错类型"，不给人名、号码、原话 |
| 公开的配置项（端口、路径结构） | 能 | 用于排查和文档 |

判据很简单：**凡是"只有这台机器上那两个人之间才知道"的内容，都不出去。**

## 9 记忆库的访问控制

现在**没有独立的鉴权层**，靠的是三件事叠起来：

1. 数据库文件在 `%USERPROFILE%` 下，只有本 Windows 账户能读
2. 库只被本地进程打开，**不监听任何端口**，网络上根本够不着
3. 8799 那个小服务明确不碰记忆库（代码里就三个路由）

所以"谁能读到记忆"这个问题，答案等于"谁能登录这个 Windows 账户"。这一层是 Windows 在管，不是大肥鱼在管。

要加真鉴权（比如局域网访问、多设备同步），是另一件事，现在没做。

## 10 多 Windows 账户的边界

- 数据跟着账户走：A 账户看不到 B 账户的记忆，因为路径就在各自的 `%USERPROFILE%` 下
- 同一个账户里跑两套实例（工作 / 大肥鱼），靠**不同数据根 + 不同 user-data-dir** 隔开，不是靠账户
- 共享的是同一块磁盘和同一个账户身份，**文件权限上也读得到**——所以实例隔离是"不互相看"，不是"看不到"

真要防人，得靠 Windows 账户本身。
