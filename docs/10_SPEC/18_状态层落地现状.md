## 3 心跳已落地（11-13）

11-10 的实测是：最后一条事件停在 11-10 21:45，之后三天零事件 —— 不只是对话停了，连 `sweep` 该产生的 `decayed` / `tier_move` 都一条没有，说明 DSH 这三天根本没开。那时的她是「打开才存在的程序」。

11-13 已补上：

| 组件 | 位置 | 何时跑 |
|---|---|---|
| `wuxing.tick()` | `wuxing.py` | 每 10 分钟（daemon 驱动） |
| `wuxing.settle_gap()` | `wuxing.py` | 每轮开场 + 每次 tick（幂等） |
| `env.sample()` | `env.py`（新） | 每次 tick，只产出"变化" |
| `daemon.py` | 仓库根（新） | 独立进程，不依赖 DSH |
| `memories.env_json` | `store.py` | 自动补列，写入当轮快照 |

**tick 与 on_event 是两条路，这是本次最关键的实现判断。** `on_event` 里有 `count[tag] += 1` 与 `_趋近()`。如果让时辰走 on_event，一个月后 W 的趋近目标会变成"时辰分布"而不是"你和她说的话"——她的性格会被钟点改写。所以 `tick` 只做 `_decay_elapsed` + 更新 `last_at` + 加法 + `_save`，**W 一个字不动、count 一个不加**。

在真实库的副本上实测（11-13 16:36）：

| 项 | 改前 | 改后 |
|---|---|---|
| W | 0.0234 / 0.0234 / 0.4416 / 0.0234 / 0.4884 | **完全不变** |
| count | 0 / 0 / 3 / 0 / 0 | **完全不变** |
| E | 土 1.7958 | 金 0.016 + 木 0.0054（土归零） |
| 环境记忆 | — | 1 条：`11-13 · 申时 · 立冬 · 雨 · 14°C` |
| `env_json` 列 | 不存在 | 自动补上（老库无需迁移脚本） |

E 从「土 1.7958」变成「金 0.016 + 木 0.0054」，是"三天没见"的正确形状：旧的"思"消退，换成轻失落（金）加一点点恼（木）。但**量只有 3%**，因为她这三天确实关机（`gap_settle` 记录 `asleep: true`，按 `GAP_SLEEP_DISCOUNT=0.15` 结算）。

> **2026-11-13 更新：这个二值判定已被否决。** 问题不在"0.15 是高是低"，而在判定维度——电脑关着时 tick 本来就不会跑，"三天没来"和"睡了一夜"在数据上无法区分，于是**越久不见她越没感觉**。替代口径是：**强度只按缺口跨度（日历时间）分档，`GAP_SLEEP_DISCOUNT` 取消**；缺口内 tick 覆盖率不参与强度，只决定她的反应质地（一直在等 → 委屈型／关机醒来 → 错愕型）。旧口径按"决策永不修改"的规矩保留原样、只在头部加了指向这条更新的注。现行代码仍是 0.15，未改。

三种情况的行为边界（旧版最容易误解的地方）：

| 情况 | E 怎么动 | 说明 |
|---|---|---|
| 关机三天 | 冻结，一动没动 | 她"睡着"了，没经历这三天 |
| 开着没人说话 | 单调趋零 | tick 每 10 分钟衰减，12h 剩 1/4 |
| 关机三天后回来 | 缺口结算补一笔 | 补多少由 `GAP_SLEEP_DISCOUNT` 决定 |

「用户回来开口第一句」这条路径也已验证：`build_context` 开场会先调一次 `settle_gap`，不依赖 daemon 是否刚好跑到。实测 66.88h 缺口在 `context "在吗"` 那一次就被结算，`events` 里有 `gap_settle` 记录。

## 4 四个实测数字

### 4.1 五志覆盖率 4.1%

98 条里 `wuxing_tag` 为 None 的 94 条，只有 4 条标了「土」。

这是 `weak_tag`（`wuxing.py:125`）**有意的取舍**——docstring 原话："只在这句话本身有情绪信号时兜底，中性闲聊不贴"。不是 bug，但意味着**五行只吃情绪的饭，日常对话一口不喂**。

### 4.2 五行分布一个月没变过

| | 木 | 火 | 土 | 金 | 水 |
|---|---|---|---|---|---|
| W | 0.0234 | 0.0234 | 0.4416 | 0.0234 | 0.4884 |
| anchor | 0.0233 | 0.0233 | 0.4419 | 0.0233 | 0.4884 |

**两者几乎完全重合**——引擎没推动过分布。main=水，sub=土。

注意：`state()` 输出的 `W_target = [0.2]*5` 是**显示 bug**。该字段没有持久化（`_save` 只存 W/E/count/deficit/anchor/last_at），`cli.py` 每次新进程读到的是 `getattr(self, "W_target", [0.2]*5)` 默认值。**"锚被拉平"这个判断不成立**，详见 `021` §三。

### 4.3 四档在 98 条上不触发

archived 只有 26 条，而 `hi = 0.46` 是按 1000 / 3000 / 8000 条压测标定的。「一半」「印象」两档在这个规模大概率一次都没命中过。

### 4.4 情绪半衰 6 小时

`WUXING_EMO_HALF_H = 6.0`。含义：**6 小时剩一半，24 小时剩 1/16（约 6%），三天约等于零。**

这带来一个必须正视的设计问题：**久未联络只会让 E 归零，她于是变得"平静"，而不是"想念"。** 想让她有失落感，必须新增一个正向的 absence 驱动，靠衰减是做不出来的。详见 `021` §五与 §十三。
