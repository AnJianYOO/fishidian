## 1 安装（已实现）

入口：包根的 **`install.cmd`**（双击），它调 **`install_v1.ps1`**，九步：

| 步 | 做什么 |
| --- | --- |
| 0/9 | 前置检查：DSH 是否在跑（在跑就 Die）、**Node ≥18 / Python ≥3.8 真判**（不足就 Die）、DSH 自带 pnpm 就位 |
| 1/9 | 建目录：`data\` `workspace\` `config\` `logs\` `backup\` |
| 2/9 | robocopy 六个 payload 目录 + 拷 `launch.ps1` `check_napcat.ps1` `verify_install.ps1` **+ 五份文档**（含 `QQ桥怎么用.md`），末尾写 `python-path.txt`（见 §1.2.2） |
| 3/9 | QQ 身份与本地口令（问机器人号 + 白名单两个值，见下） |
| 4/9 | 写 profile：`cordis.patch.yml`（**三占位符替换**）、`package.json` |
| 5/9 | profile `pnpm install` + 桥只装 `ws`（`autoInstallPeers: false`）+ 验真目录 |
| 6/9 | NapCat 体检（`-SkipNapCat` 跳过） |
| 7/9 | 桌面快捷方式（`-NoShortcut` 跳过） |
| 8/9 | 内核自检：建新库跑一次 `cli.py state` |
| 9/9 | 打印安装位置 + 指向 `$Target\START-HERE.md` + **给一条 `verify_install.ps1` 命令** |

**0/9 的版本判断是硬门槛，不是提示**：桥用到 `fetch`（`bridge.js:98` 等 12 处）、`AbortSignal.timeout`、`structuredClone`（`store.js:158`），这三个都是 Node 18 才有的内置 API —— Node 16 能把包一路装完，只在 QQ 通道启动时挂掉，且错误不指向版本。所以 `install_v1.ps1:89` 起改成交判一次（走 `Invoke-Native` 避开 `$ErrorActionPreference=Stop` 下 native stderr 抛异常的老坑），不足直接 `Die` 并说明"装完重开命令行，旧窗口 PATH 不更新"。

Python 由同样逻辑判 `≥3.8`（实测内核无 `match`、无 `removeprefix`、全部 `from __future__ import annotations`，3.8 可跑），且覆盖 Microsoft Store 占位 stub —— `Get-Command python` 能找到、`python --version` 却退出码非 0，这种也按失败处理。

**问两个值**：机器人 QQ 号 + 白名单（谁有资格和她说话）。机器人号留空写占位 `0`，QQ 通道等补号才通；机器人号有效时白名单单独问一次，可填多个（英文或中文逗号分隔，最多 5 个）。

**填了号要过格式校验**：只接受 `^[0-9]{5,12}$`（真 QQ 号都满足）。带尾随空格、全角数字、字母的输入会被**判成"填错"并按未填处理**（写占位 `0` + `Warn` 说明怎么补），而不是原样写进 YAML —— 桥启动时把非数字转不成号，通道静默不启用，要等到点「连 QQ」才看出问题。

> 早前设想的"问三句（称呼 / QQ 号 / 允许谁）"里，称呼确实改由首启卡片问；但**白名单必须问**，不能默认成机器人号 —— 那样用户自己的号不在名单里，装完表现为「QQ 发了她不回」。现在稳定为两句：机器人号 + 白名单。

**4/9 替换四个占位符**：`__WEBHOOK_TOKEN__` / `__BOT_QQ__` / `__ALLOW_USERS_LINES__` / `__ALLOW_USER__`。前三个是整值，`__ALLOW_USERS_LINES__` 是**整行占位**（模板里单独一行，安装器展开成 `      - 号` 的多行）；`__ALLOW_USER__` 仍取第一个号，供 `webhookSources[0].chat` 与 `proactive.webhook.chatKey` 当"主用户"。早前还有 `__PROJECT_ROOT__` 与 `__MEMORY_DIR__` 两个，随 `cordis.patch.yml` 里 `python` / `core` / `db` 三个死键一起删掉了（路径改走环境变量，见 §1.2.2）。

### 1.2.2 内核路径怎么定的（`FISHIDIAN_*` 三件套）

这一段最容易踩空。**插件的 `apply(ctx, config)` 只取 `config.ns`**，`cordis.patch.yml` 里原来写的 `fishidian.python` / `.core` / `.db` 三个键**从来没有人读**。真实生效的是三个环境变量，由 `launch.ps1` 在 `Start-Process` 起窗口之前打进子进程环境：

| 环境变量 | 由 `launch.ps1` 设成 | 不设会怎样 |
| --- | --- | --- |
| `FISHIDIAN_CORE` | `<安装根>\fishidian-core` | 插件走逐级向上查找；`node_modules` 布局下能到安装根，但多绕几层，且极端情况下会落到打包时那台机器的 `D:\` 路径 —— `cli.py` 不存在，`spawnSync` 静默失败 |
| `FISHIDIAN_DB` | `<安装根>\workspace\memory\dfy.db` | `dbPath()` 落到 `~\.dsh\fishidian-memory\fishidian.db`；**在打包那台机器上一直没暴露，是因为遗留库 `~\.dsh\dafeiyu-memory\dfy.db` 恰好存在，纯巧合**。干净机器上没有它，库就建到 `.dsh` 下，和文档写的路径不一致 |
| `FISHIDIAN_PYTHON` | `python-path.txt` 里的绝对路径 | 落到裸 `"python"`。GUI 进程 PATH 未必含它，`spawnSync` 全部失败 → 她"失忆"但零报错 |

**这三条的共同失败形态是"没有任何报错，只是每轮都当第一次聊天"。** 所以 `verify_install.ps1` 单列了「4.5 内核路径」一节专查它们，`launch.ps1` 在找不到时也会打印提示。

`python-path.txt` 存在的理由：快捷方式拉起的进程和用户在终端里敲命令的 PATH 可能不同（刚装完 Node / Python 没重开资源管理器就是典型症状）。所以安装期探测到的绝对路径落一份文件，`launch.ps1` 先读它、读不到再现找；不写死在脚本里，因为用户以后可能升级或挪位置。

对应代码位置：`dsh-fishidian\lib\index.js` 的 `PYTHON`（第 28 行）、`_resolveCore()`（env → 逐级向上找 `fishidian-core\cli.py`，最多 8 级）、`dbPath()`（`FISHIDIAN_DB` → `FISHIDIAN_DB_DIR` → `~/.dsh/fishidian-memory/` → legacy）；`tools\launch.ps1` 的 `[2.5]` 段。

### 1.2.1 装完验证（`verify_install.ps1`）

`START-HERE.md` 原来让人肉眼核四条（窗口能开 / 记忆库长大 / 两套分开 / QQ 通了）。问题在于"窗口开得出来"很容易误判 —— 插件没链上、`ws` 没装、QQ 号还是占位 `0`，窗口照样开。所以补了一个只读脚本，装完立刻能跑：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "%USERPROFILE%\fishidian\verify_install.ps1"
# 装到别处：-TargetRoot "D:\fishidian"
```

退出码 `0` = 无硬失败，`1` = 有硬失败。输出 `[OK]/[FAIL]/[WARN]` 三级 + 汇总行。查七类：

| 类 | 内容 |
| --- | --- |
| 运行时 | node ≥18、python ≥3.8（与 0/9 同标准，失败路径会给可操作的提示而不是抛异常） |
| 安装根 | `launch.ps1`、`check_napcat.ps1`、`tools\qq-qrcode-server.js`、`START-HERE.md`、`fishidian-core\cli.py`、桥 `lib\bridge.js` / `lib\onebot.js`、`dsh-client-ui-fatfish\lib\index.js`、`dsh-fishidian\lib\index.js` |
| profile | `package.json` 含三个 `link:` 依赖；`node_modules` 下三个包真链上 |
| 桥 ws | `node_modules\ws\package.json` 在且 **`LinkType` 为空**（真目录，不是 junction —— junction 换机器就断） |
| 配置 | `cordis.patch.yml` 存在；`botQq` 不是占位 `0`；`allowUsers` 有值 |
| 数据目录 | `workspace\memory`、`workspace\sessions`、`logs`、`backup` |
| 内核路径 | `launch.ps1` 里能搜到 `FISHIDIAN_CORE` / `FISHIDIAN_DB` / `FISHIDIAN_PYTHON`；`python-path.txt` 存在且路径有效；插件 `lib\index.js` 支持 `FISHIDIAN_DB`；`cordis.patch.yml` 无死键（见 §1.2.2） |
| 内核 | `cli.py state` 退出码 0（用同一个 db 建库，与首次开窗口等价） |

**脚本判不了的四条仍然要人看**：窗口开出来长什么样、聊几句后 `dfy.db` 是否在长、工作 DSH 里说的话她是否答不上来、QQ 是否真通。

**接线**：`build_v1_package.py` 的 `build_scripts()` 从 `tools\` 取它（与 `install_v1.ps1` / `launch.ps1` / `check_napcat.ps1` 同列）；`verify_v1_package.ps1` 第 1 段 `$rootFiles` 与第 2 段 `$ps1s` 均已登记，所以它同样受 BOM / CRLF / 5.1 语法三项硬检查。包自检现在是 **52 项**，其中三类是后来补上的：死键回归、废弃占位符、四个 ESM 文件的 `node --check`。

## 2 升级与降级判定（未实现，设计如下）

| 现在装的 | 要装的是 | 行为 |
| --- | --- | --- |
| 无 | 任何 | 全新安装 |
| V1 | V1 更高 | 允许，替换程序，保留数据 |
| V1 | V2 | **允许，这是升级** |
| V2 | V2 更高 | 允许 |
| V2 | V1 | **拒绝**：降级 |
| V2 | V2 更低 | **拒绝**：版本回退 |

拒绝时用人话说："你电脑上装的是窗口版，比这个包还新。要换回 QQ 版，得先把现在的卸掉。"

### 2.1 升级换什么、留什么

**换**：`fishidian-core\` `dsh-fishidian\` `dsh-client-ui-fatfish\` `dsh-qq-onebot-bridge\` `tools\`、桌面图标、`VERSION.txt`
**留**：`workspace\`、`config\`、`backup\`、`logs\`、`data\`

**唯一例外：`data\profiles\desktop\cordis.patch.yml` 必须合并，不能覆盖。** 新版本从旧文件取出 `botQq`、`allowUsers`、`token` 三项写进新模板，其余用新模板。直接覆盖会让用户的 QQ 号和白名单凭空消失。

### 2.2 升级失败要能退回

替换前先把旧目录改名成 `*.old`，装成功再删，装失败改回来。**不能先删再装**——删完装挂了用户就什么都没有。

## 3 卸载（未实现，设计如下）

### 3.1 入口

1. 桌面图标右键 → 卸载
2. 安装根里的卸载脚本（V1 未写）
3. Windows"应用和功能"（待补，需注册表登记）

> **V1 实际现状：三个入口都没有**，只能手动删 `%USERPROFILE%\fishidian\` 整个目录。文档已写明这会连记忆一起删。

### 3.2 卸载前必须停进程

DSH 实例、二维码小服务（8799）、桥。停不掉就告诉用户"她还在运行，先把窗口关掉再来"，然后退出，**不硬删**。删一半留一半比不删更糟。

### 3.3 分项勾选（按版本裁剪）

**V1：**

```
[必选] 大肥鱼本体
[ ]    NapCat
[勾]   开机自启
```

**V2：**

```
[必选] 大肥鱼本体
[ ]    NapCat
[勾]   开机自启
[勾]   把工作窗口恢复原样
```

第四项**只在检测到工作窗口确实被改过时显示**，判断方法是读工作窗口 profile 里有没有她的皮肤补丁。

默认值：

| 项 | 默认 | 理由 |
| --- | --- | --- |
| 本体 | 必选 | 卸载动作本身 |
| NapCat | 不勾 | 第三方工具，可能还在给别的用 |
| 开机自启 | 勾 | 不清掉会导致开机尝试启动不存在的程序 |
| 工作窗口恢复 | 勾（仅 V2，且仅检测到改过） | 鱼卸了，工作窗口还留痕迹很怪 |

> **V1 实际现状：没有开机自启这一步**（新安装器不含），这条暂时无对象可清。

### 3.4 记忆不参与卸载

**没有"删除记忆"这个选项，不是默认不勾，是根本没有。** 卸载是不可逆动作，删记忆是不可逆决定，两件事不该出现在同一个确认框里。

卸载完打印路径：

```
她的记忆还在这里：
  C:\Users\<你>\fishidian\workspace

  不打算再用了，可以把这个文件夹整个删掉。
  以后想让她回来，重新装一次就行，她还记得以前的事。
```

### 3.5 NapCat 的归属

建议独立，不删。第三方工具不该由安装器删。卸载完提示一句它是什么、在哪。
