# 12 日志与报错

> 状态：有效（规范已定，代码未落地）｜ 最后更新：2026-11-10 ｜ 对应版本：通用
> 为什么 error 要单独一份：出事时要能一眼看出是哪一层失败。

## 1 四类日志

全部在 `<安装根>\logs\`（默认就是 `%USERPROFILE%\fishidian\logs\`）。

| 文件 | 记什么 | 保留 |
| --- | --- | --- |
| `app-YYYY-MM-DD.log` | 正常流水：启动、连上 QQ、收到消息、生成回复 | 7 天 |
| `error-YYYY-MM-DD.log` | **只记异常**，不混正常记录 | 30 天 |
| `bridge-YYYY-MM-DD.log` | QQ 桥收发，一进一出 | 7 天 |
| `audit-YYYY-MM-DD.log` | 谁什么时候来过、她主动发了什么 | 90 天 |

目录名用中文，文件名用英文前缀——文件夹给人看，文件名给 grep 和脚本看。

## 2 error 必须独立的原因

它要在出事后一分钟内被交出去。混在 app 日志里就是几千行正常记录夹几行红字，用户翻不到，排查的人也得从头筛。`error-` 打开就是纯粹的坏消息，一天可能只有三五行。

## 3 一条 error 的四要素

1. 时间，精确到毫秒
2. 模块：`[qq-bridge]` / `[proactive]` / `[kernel]` / `[install]`
3. 异常类型 + 一句人话
4. 上下文：输入是什么、断在哪步、重试第几次

好例子：
```
2026-11-10 22:31:07.412 ERROR [qq-bridge] 发送失败 err=ECONNRESET target=***7675 step=send retry=2/3
```

禁止写法：`Exception occurred`、`Error: failed`、`[error] 出错了`。

## 4 用户能自己处理的事，补一行大白话

在 ERROR 下一行缩进，用 `└─` 起头：

```
2026-11-10 22:31:07.412 ERROR [qq-bridge] 发送失败 err=ECONNRESET target=***7675 retry=2/3
2026-11-10 22:31:07.412  └─ 她已经和 QQ 断开了。重新扫一次码就好。
```

覆盖八类：

| 情况 | 补的话 |
| --- | --- |
| QQ 掉线 | 她已经和 QQ 断开了。重新扫一次码就好。 |
| QQ 没登录 | 她的 QQ 还没登录，扫个码就能收消息了。 |
| 磁盘空间不够 | 这台电脑空间不够了。清点东西，或者把文件夹挪到别的盘。 |
| 没有写权限 | 她没法往自己的文件夹写东西。看看是不是只读，或被安全软件锁了。 |
| 杀软拦截 | 安全软件可能拦住了她连 QQ。加进白名单再试一次。 |
| DSH 没登录 | 你还没登录 DSH，她没法用自己的额度说话。登录一次就好。 |
| 端口被占用 | 她要用的端口被别的程序占了。关掉那个程序，或者重启。 |
| 网络不通 | 网断了。看看网线或 WiFi。 |

**其余错误保持技术原样。** 数据库忙、超时、内存溢出这类，用户看了也不知道怎么办，硬加解释反而让他以为是自己弄坏的。

判断标准：用户看完能不能自己动手解决。能就写人话，不能就留给工程师。

## 5 脱敏

| 对象 | 处理 |
| --- | --- |
| token / WebUI 口令 | 前 4 位 + `***` |
| QQ 号 | 只留后 4 位，`***7675` |
| 对话正文 | 只记 `text_len=42 hash=a3f9` |
| `sk-` 密钥 | 一个字符都不记 |

脱敏在 logger 的写入口做硬过滤，不靠每个调用点自觉。

## 6 用户怎么交出来

三个入口：

1. **导出日志按钮**（v0.2 在窗口里，v0.1.0 在托盘右键）——打包最近三天到桌面
2. **崩溃自动打包**——连续崩三次，自动打包并在下次启动提示
3. **安装失败**——`install.log`，提示「把这个贴到 Issue」

第 2 条最要紧：用户遇到问题往往就在崩溃那一瞬间，让他事后自己翻文件夹是翻不到的。

## 7 轮转与清理

- 单文件超 20 MB 切 `-2`、`-3`
- 01:00 压缩前一天的为 `.gz`
- 02:00 清超过保留期的
- UTF-8 无 BOM、行尾 `\n`、每行立即 flush（崩溃时最后几行才是关键）
