# 14 账号与白名单

> 状态：规范已定，设置页未实现 ｜ 最后更新：2026-11-10 ｜ 对应版本：通用
> 单一事实源见 `11` 第 4 节。分工的来由不在这里展开，只写现在怎么分。

## 1 入口：一个本地设置页

做成网页，用系统默认浏览器打开，复用 8799 小服务加一个 `/settings`。

不放在窗口里做表单的原因：V1 没有窗口也得能用，一套界面两版共用，以后加项只改网页。

| 版本 | 怎么进 |
| --- | --- |
| V2 | 侧栏「用户选项」→ 设置 |
| V1 | 托盘右键 → 设置 |
| 都有 | 安装根里的设置脚本（V1 未写） |

第三个是兜底，因为托盘图标可能被 Windows 收进"隐藏的图标"里。

## 2 页面结构

### 2.1 顶部：当前状态

- 用的 QQ 号
- 连接状态（● 已连接 / ○ 还没登录）
- 允许谁找她
- 「换一个 QQ 号」按钮

"连接状态"这一行必须有，因为用户最常问的就是"她到底连上了没有"。

### 2.2 中部：白名单

每行：备注名 + 号码（默认打码到后四位）+ 改备注 / 移除。
底部「添加一个」，只输 QQ 号，备注可选。

### 2.3 底部：两个开关

- 她可以主动找你
- 随电脑启动

这两个就是新手指引里问过的两件事。**指引问一遍，设置页永远能改**——不然当时随手点的，以后没地方改。

## 3 换 QQ 号：五步引导，不是输入框

**不能直接放输入框让人改。** 一个号散落在四个地方，其中两个文件的名字里就带 QQ 号，改错一处就互相矛盾。

| 位置 | 存了什么 |
| --- | --- |
| `config\setup.json` | `botQq`、`allowUsers` |
| `data\profiles\desktop\cordis.patch.yml` | `botQq`、`allowUsers`、`token` |
| `NapCat\config\napcat_<QQ号>.json` | 文件名带号 |
| `NapCat\config\onebot11_<QQ号>.json` | 文件名带号 |

流程：

1. **说清后果**——新号要重新登录，旧的退出，记忆不受影响
2. **输新号并校验格式**（5–12 位数字），当场报错，不拖到最后
3. **停掉一切**——NapCat、她、小服务。提前告知"窗口会关掉，是正常的"
4. **换配置起新登录**——复制两份 napcat 配置改名、改账号字段、更新两处 `botQq`、清旧登录缓存、重起、弹码
5. **扫码**——和首次安装同一套：出码 → 等扫 → 轮询 → "好了，她现在用新号了"

### 3.1 失败必须回滚

动手前先把 `config\` 和 `data\profiles\` 备份到 `backup\manual\`。任何一步失败，恢复旧号并提示"没换成，已经恢复成原来的号了"。

**绝不能让用户落在既不是旧号也不是新号的状态里。**

## 4 白名单：改完立即生效

白名单不需要重新登录，改完就该马上生效。现在实现是启动时读一次、之后用内存那份——**这一处要改成每次收到消息读当前配置，或保存后发一个重载信号**。否则用户加完人还得重启。

### 4.1 用户不知道对方 QQ 号怎么办

页面上给一句提示：对方的 QQ 号在他自己的资料页能看到。

以后开了好友圈模式（从好友列表里认人），这里可以变成"从你的好友里挑"。

## 5 只支持一个 QQ 号

设置页只显示一个当前账号，「换一个」是替换不是新增。技术上能跑两个，但那样她有两个身份、记忆怎么分又是新问题。**一个人格比两个通道重要。**

## 6 安全

1. 只监听 `127.0.0.1`，不监听 `0.0.0.0`
2. 带随机 token，启动时生成并写进 URL
3. 改任何东西都必须 POST，不接受 GET 改状态（防止别的网页用 `<img src>` 改白名单）
